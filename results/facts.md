Conventions: P_fail = logical failure probability per shot; ε = logical error per round = ½[1 − (1 − 2 P_fail)^(1/T)]; f = (ε_A − ε_X)/(ε_A − ε_B) = fraction of the perfect-flag (oracle) gain recovered; McNemar counts are "shots only the first decoder gets right / shots only the second gets right", exact two-sided binomial p.

## F1. The method (what is fixed in all experiments)
- Code: rotated surface code memory (Stim `surface_code:rotated_memory_z`), background noise SI1000 with strength p. Leakage model (phenomenological, leakage_sim.py): each data qubit leaks with probability p_L per round and stays leaked for a geometric time of mean τ rounds. While leaked, it FLIPS each adjacent check outcome with probability ρ = 1/2, independently per check and per round (`coins < rho; flips = leaked & coins`). On return it receives a Pauli drawn uniformly from {X, Y, Z} (`rng.integers(0, 3)`), which is what the weight constant c = 2/3 assumes. If leaked at the final readout, its readout bit is flipped with probability ρ. Do not write "randomises with probability ρ".
- Decoder rule (same for every tracker): per shot, every matching-graph edge e touched by a possibly-leaked qubit gets probability p_e ← p_e ⊕ c·π, with c = ρ for the time-like edges of adjacent checks, 2/3 for the X/Z data edges at the return round, ρ for the final data-readout edge; π < 0.02 ignored. Derivation: derivation_soft_weight.md. PyMatching 2.4 minimum-weight matching.
- Trackers: (i) old HMM (per-qubit 2-state hidden Markov model, detection events treated as independent across rounds, true parameters given); (ii) old CNN, a small network: 3 causal 3×3×3 conv layers, 32 channels, trained on 5×10⁴ simulated shots with true leakage labels, 6 epochs, lag 2; its learning curve was still rising at 2×10⁵ shots (F2); (iii) **ALL** (xa_tracker.py v2): per-data-qubit HMM whose hidden state also contains the measurement-flip bit of each neighbouring check ("explaining away"), all neighbouring checks of both bases, the given undecomposed detector error model, 8 damped Jacobi mean-field passes (damping 0.5) between neighbouring data qubits, label-free Baum-Welch calibration (12 iterations from p_L = 3e-3, p_ret = 0.25), ρ fixed at 1/2. Source: detect2_protocol.md v2.
- What is learned and what is given: Baum-Welch learns one p_L per data qubit and one global return probability p_ret from the device's own syndromes (calibration shots that are never decoded). ρ is fixed. The background error model is NOT learned: in simulation it is the exact circuit DEM; on hardware it is the p_ij DEM shipped by the authors of the data. A mismatch of that given model is what produces the false alarms of F6. Because p_L is learned per run, there is per-run calibration; there is no hand tuning.
- Controls: A = plain MWPM; B = oracle (true flags; simulation only); A4 = static control (each shot gets the mean posterior over all shots); P = placebo (each shot gets another shot's posteriors, fixed permutation seed 0). Source: ibm_stab_protocol.md.
- Compute cost: 450 s per 40 000 shots of 25 rounds on 12 cores, about 0.45 ms per shot-round, against hardware rounds of about 1 μs. Offline, full-record smoothing.
- Endpoint criteria: P1 = AP(ALL) above both old trackers in all 4 primary detect2 cells; P2 = pooled exact two-sided McNemar over the 4 primary cells, ALL vs CNN and ALL vs HMM, p < 0.05 with ALL ahead; PR1 = X vs A p < 0.05 with X ahead, X vs A4 p < 0.05 with X ahead, and P not significantly better than A, all pooled over the 17 ibm_berlin stability runs; v3 rule 1 = in the three leak-free scenarios McNemar must not favour MWPM at p < 0.05.

## F4. Real data: nulls (history)
- Google 2023 Sycamore (Zenodo 6804040; real_data_report.md): pooled over eight d = 3 patches (400 000 shots) soft weights are 0.7 to 1.4 % WORSE (HMM ratio 1.014 [1.006, 1.021]; CNN lag 2 1.008 [1.001, 1.016]); null at d = 5 (ratios 1.000 to 1.011). The static control A4 is the only decoder that helps (−0.5 % d = 3, −1.4 % d = 5). A simulator fitted to each experiment predicts the same null: perfect flags would remove only 2.9 % (d = 3) / 9.9 % (d = 5) of ε. Detection fraction 0.14 to 0.17. Protocol status: the tracker settings and the soft-weight rule were fixed by c3_preregistration.md; this analysis had no separate protocol of its own, and its scripts are not in the repository.
- Google 2025 Willow (Zenodo 13273331, d3_at_q6_7/Z/r30; willow_scope_report.md): scope null predicted before decoding and confirmed. Detection fraction flat at 0.0763 in rounds 1 to 28 (slope −2.4 ± 1.0 ×10⁻⁵ per round); leaked population bounded to ≤ 0.1 % of data-qubit-rounds for τ ≥ 2; all soft decoders within ±2 % of MWPM, none significant after Holm correction (best: CNN lag 2, SI1000 prior, 0.980 [0.960, 0.999], p = 0.049, not reproduced with the RL prior: 0.987 [0.968, 1.007]). Google removes data-qubit leakage every cycle (DQLR). Bound method: every noise probability of the generic SI1000 circuit scaled by one factor s fitted to the mean detection fraction; grid τ ∈ {1,2,3,4,8,16} × p_L; 50 000 simulated shots per point; 95 % limit Δχ² ≤ 3.84 on the SHAPE of the detection-fraction curve over rounds 2 to 29. Upper limits: 0.06 to 0.11 % of qubit-rounds for τ = 2 to 16; τ = 1 not bounded by the curve. Protocol status: same as Google 2023 (settings fixed by c3_preregistration.md, no separate protocol; adaptive_protocol.md was written for Willow but never executed; scripts not in the repository).
- IBM ibm_berlin MEMORY runs (Zenodo 23335425; ibm_results.md, old per-detector tracker, ibm_protocol.md frozen 21 Oct 2026 before any tracker-based decoding): KILLED on 10 held-out runs (q85, d = 3 and d = 5, T = 5 to 50): X vs A 84805 / 85268 (p = 0.26); X loses to the static control A4 (49389 / 53169). Diagnostics showed a persistent per-detector hidden state (continuation probability rising from 0.31 to 0.39 at k = 1 to 0.60 to 0.72 at k = 12 to 14 consecutive firings; flat 0.33 to 0.46 under the shipped DEM) and a detection fraction rising with T (d = 5: 0.17 at T = 5, 0.28 averaged at T = 50). These memory diagnostics on the same chip motivated the ALL design (explaining away, both bases); state this in Limits.

## F5. Real data: the positive result, IBM ibm_berlin STABILITY (17 unseen runs), source: ibmstab_results.md, ibmstab_tables.md, ibmstab_aggregate.json, ibm_stab_protocol.md, ibmstab/null_evidence_summary.md, ibmstab/mwpm_vs_lange.md
- Data: Lange et al. arXiv:2610.03869, Zenodo 23335425, `stability_d3`: d = 3 X-type stability experiment on IBM Nighthawk r1 (ibm_berlin; the chip name is our reading of their paper, re-check before quoting), 7 data qubits, 8 measure qubits; T = 5, 10, 20, 50, 100 (100 000 shots each) and a pre-readout rotation α ∈ {0.15, 0.3, 0.45, 0.6, 0.8, 1.0} rad at T = 20 and T = 100 (50 000 shots each). The base runs are α = 0. None of these runs was used in any earlier analysis. Protocol frozen 25 Oct 2026 before any logical outcome was read. Tracker = ALL as frozen in detect2, no change. Calibration shots: min(10 000, 200 000/T) per run, drawn at random, never decoded. Round time of the hardware: not in our records; the μs conversion of episode lengths needs it from Lange et al.
- Adapter: the shipped p_ij DEM matches the authors' stability circuit (circuits/stability_d3_X.stim) mechanism by mechanism (823/823 at T = 10; 1723/1723 at T = 20). gen_leaky.py.
- Baseline check against the authors (ibmstab/mwpm_vs_lange.md): our plain MWPM (decoder A) reproduces the MWPM P_fail that Lange et al. ship in their results/ibm_stability_d3.json on all 17 runs: |z| ≤ 2.04, mean z +0.4, 11 of 17 within one standard deviation (e.g. T = 100: ours 0.0228 on 98 000 shots, theirs 0.0204 ± 0.0014 on 10 000). This shows that A is the same baseline they used (same model, same decoder); it says nothing about whether that model is the best possible baseline.
- Provenance of the shipped p_ij DEM: estimated from the detection-event correlations of the same run with the authors' scripts/calibrate_dem.py (correlator ratios for error mechanisms flipping up to four detectors, arXiv:2502.17722 App. E). Not a device-calibration model. Running that script on the events as we read them reproduces the shipped DEM term by term (373/373 at T = 5, 1723/1723 at T = 20, max difference < 1e-6).
- The shipped DEM over-predicts the detection fraction on every run when sampled with Stim's own sampler: 0.176 vs 0.142 in the data at T = 5; 0.231 vs 0.161 at T = 20; 0.317 vs 0.210 at T = 100. Its one- and two-detector terms alone give 0.099 at T = 5, so the three- and four-detector terms carry the excess. Our reading (not verified with the authors): the calibration matches correlators, not marginals, and correlated noise outside its error set inflates the hyperedge estimates. Plain MWPM uses only weight ratios, which is why A still matches their numbers.
- **Primary endpoint PR1: MET.** Pooled over 17 runs: X vs A 11 374 / 8 502 (p = 1.7e-92); X vs static A4 10 389 / 8 859 (p = 2.8e-28); placebo P vs A 3 346 / 4 959 (p = 1.9e-70, placebo worse). Prediction before the test: P(met) ≈ 0.25.
- Gain vs T (α = 0): change in P_fail X vs A: T = 5 −0.5 % [−1.8, +0.7]; T = 10 −0.6 % [−2.2, +1.0]; T = 20 −5.8 % [−7.6, −3.9]; T = 50 −15.3 % [−17.5, −13.0]; T = 100 −20.4 % [−23.0, −17.7] (P_fail 0.0228 → 0.0182). Per-run X vs A: T = 20 1505/1199, T = 50 1353/774, T = 100 827/371. On ibm_berlin the tracker removes at most 20 % of failures.
- Static control: A4 vs A −4.4 % (T = 5) to −1.0 % (T = 100). X vs A4 per run: 11 wins (one of them, T = 20 α = 0.8, by 2 shots to 0), 3 losses (T = 5, T = 10, T = 20 α = 0.6), 3 exact ties (T = 20 α = 1.0, T = 100 α = 0.8, T = 100 α = 1.0). α ≥ 0.8 covers 4 runs. Placebo: −0.5 % (T = 5) to +12 % (T = 100).
- Rotated readout: for α ≥ 0.8 the calibration fits mean p_L 0.7e-4 to 5e-4, p_ret 0.2 to 0.5, evidence ≈ 0 nats/shot; X = A within 2 shots per run. Wording: when readout noise buries the signal, the fit returns near-zero leakage and the decoder falls back to MWPM. It is the same chip and presumably the same state. Do not write "nothing to find". At T = 20 the gain is not monotone in α (−5.8 % at 0, −8.0 % at 0.3); it vanishes for α ≥ 0.8. At T = 100, α = 0.6: X vs A −6.4 % [−8.5, −4.1], X beats A4 (A4 vs A −2.5 %). At T = 20, α = 0.6: X vs A −0.1 % [−1.5, +1.4], loses to A4.
- Label-free evidence (log-likelihood of the fitted model minus the no-leakage model, per calibration shot): 1.0 (T = 5) to 8.2 (T = 100) nats at α = 0, i.e. 0.20 and 0.08 nats per round; per-shot nats grow with T by construction. Exact: 0.97, 1.75, 3.14, 5.93, 8.16 at T = 5, 10, 20, 50, 100.
- Null of the evidence (ibmstab/null_evidence_summary.md; leak-free shots sampled from each run's shipped DEM with Stim, seed 1000+s, same shot counts, same frozen 12-iteration calibration): 0.51 (T = 5), 0.97, 1.67, 3.17, 5.01 (T = 100) nats per shot, 50 to 60 % of the real values. Seeds 2 and 3: T = 20 1.60, 1.61 (spread 0.07); T = 100 4.85, 4.79 (spread 0.22). Real over null: 1.90 at T = 5, 1.63 at T = 100 (factor 1.6 to 1.9). α = 0.6: T = 20 null 0.81 vs real 1.37; T = 100 null 2.85 vs real 2.55 (real BELOW null). α = 1.0, T = 100: null 0.50 vs real −0.06. Fitted p_ret on null data 0.27 to 0.51 (episodes of 2 to 4 rounds); on the real α ≤ 0.6 runs 0.009 to 0.033 (30 to 110 rounds; 0.013 to 0.033 at α = 0, i.e. 30 to 77 rounds); real T = 100 α = 1.0: 0.48, null-like. Episodes of 30 to 77 rounds are longer than the T = 5, 10 and 20 runs, so in those runs p_ret is barely constrained.
- RULES FOR TEXT on the evidence: (a) never quote the raw evidence as proof of leakage; quote it next to its null. (b) The evidence gap does NOT track the decoding gain: at T = 100, α = 0.6 the evidence is below its null and the tracker still cuts failures by 6.4 %; at T = 20, α = 0.6 it is above its null and the tracker gains nothing. A per-run likelihood-versus-null switch (G2 type) would have turned the tracker off in a run where it helped. Do not write "no gap, no gain". (c) The evidence for per-shot information is X > A4 and P < A. (d) Always add that the null is drawn from a model whose detection fraction is already too high, so the gap cannot be cleanly attributed to leakage, and that a leak-free run from the same chip does not exist.
- Hot qubits: in all 13 runs with α ≤ 0.6 the two data qubits with the largest fitted p_L are the same two (indices 1 and 5; 2 to 9e-3 per round at α = 0; at T = 5 the other five are ≤ 0.14e-3). On the shipped-DEM null shots the fit spreads p_L over all seven qubits (0.45 to 2.7e-3) and the top two change from run to run and seed to seed (1 and 6, 6 and 2, 0 and 6, ...). BUT in the leak-free, uniform-noise simulation of the same circuit (N4, F6) qubits 1 and 5 also come out on top (3.3 and 3.7e-3 against ≤ 0.8e-3 for the rest, dev_v3_diag.jsonl), so part of the repetition is circuit geometry: those two positions are the most exposed. The repetition alone therefore cannot separate a physical cause from a systematic error of the given model on those qubits, and F6 shows the tracker fits fake leakage when the DEM is off by amounts that differ per qubit. Report both facts together.
- Old per-detector IBM tracker (X_old) HARMS here: +13 % to +15 % at T = 5 to 10; pooled X_old vs A 24 972 / 32 003; X vs X_old 33 401 / 23 498.
- Robustness (exploratory, post hoc): stronger MWPM with the 3-/4-detector mechanisms decomposed (A_dec) is modestly better than A (16 363 / 15 877, p = 0.0069); X on top of it still wins: X_dec vs A_dec 10 116 / 7 334 (p = 8e-99); T = 100: 0.0223 → 0.0180 (−19 %).
- Cost: ≈ 15 min per T = 100 run (calibration + tracking) on 12 cores.
- Limits: one chip, one d = 3 patch, stability only; hidden state may be leakage or a TLS-like defect (no IQ data); the ALL design was motivated by memory diagnostics on the same chip (different runs, tracker frozen before the stability data were read, so the test stands, but it is not a second chip); not compared with the authors' GNN-RNN decoder; offline (full-record smoothing). The ibm_miami Zenodo record ships raw IQ data for its fig4 memory runs; that is a possible second-chip leakage ground truth for later.

## F6. False-alarm boundary and v3 (synthetic only), source: miami_precheck.md, v3_dev_protocol.md v3, v3_dev_results.md, v3_confirmation.md, dev_v3_diag.jsonl
- On leak-free simulated data the frozen tracker ALL (v2) invents leakage: reset d = 5 memory, p = 2e-3, no leakage: Baum-Welch fits p_L 1.1e-3 with p_ret 0.98 (one-round fake episodes), P_fail 0.0174 → 0.0208 (47 / 81). On ibm_miami-style no-reset circuits (Zenodo 21336494, authors' calibration noise, no leakage): d = 3 memory exact model 0.031 → 0.044 (77 / 225); with real noise 1.7× the model 0.089 → 0.168 (359 / 1299), 0.089 → 0.110 after label-free rescaling (174 / 417); d = 5 memory with 1.5× noise 0.365 → 0.418.
- ibm_miami label-free facts: real detection fractions are 1.5 to 1.7× the authors' calibration model and rise with depth (d = 3 placement 5: 0.084 → 0.107 from depth 2 to 32). "Defects ignored" stability runs are random (published MWPM failure 0.45 to 0.49).
- v3 = R (readout explaining away for no-reset circuits) + G2 (per-run switch-off test: keep a data qubit only if its held-out likelihood gain exceeds the largest per-qubit gain on leak-free data simulated from the model). Chosen by a rule fixed in advance (dev seed 7000: no harm in three null scenarios; summed gain +0.22 vs +0.10 for the runner-up; summed gain = sum over L1, H1, L2, H3 of the net discordant count divided by the MWPM failures). **Confirmation on new seeds (8000) FAILED rule 1**: reset leak-free d = 3 memory 88 / 121, p = 0.027 (relative rise +3.4 %, 0.0503 → 0.0520). Other null scenarios: 58 / 47 (p = 0.33) and 0 / 0. Leakage scenarios: 655 / 359, 128 / 106, 154 / 109, 58 / 45. By the pre-set rule v3 was NOT run on ibm_miami.
- Oracle gains in the v3 memory scenarios L1, H1, L2, H3: 4 to 26 % (oracle 562/140, 212/116, 193/41, 141/105 on MWPM failures 1694, 1320, 588, 1255). These are the "4 to 26 %"; they do not refer to the stability diagnostic.
- Diagnostic on an ibm_berlin-type stability circuit (T = 50, uniform p = 6e-3, seed 7000, 20 000 shots): no leakage (N4) → MWPM 0 failures AND tracker 0 failures (0 / 0 discordant; this case says nothing about harm); two long-lived hot qubits at indices 2 and 6 (H4, p_L = 3e-3, τ = 40) → MWPM 0.0075, tracker 0.0034 (114 / 34, p = 3e-11), v3 0.0037 (109 / 35); the fit puts p_L on indices 2 and 6 (3.4 and 3.1e-3) and zero elsewhere. Reading, scoped to this one synthetic circuit: here the logical failures come mostly from the long-lived states, so the tracker has much to gain and little to lose; in the memory scenarios the oracle gain is small (4 to 26 %) and a few false alarms cancel it. On N4 (no leakage, uniform noise) the unguarded fit still assigns p_L 3.3 and 3.7e-3 to qubits 1 and 5 and ≤ 0.8e-3 to the rest (see F5, hot qubits).

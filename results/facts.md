# facts.md, canonical numbers for the C3 paper, the course report and the repository README

*Compiled 26 Oct 2026. Every document quotes numbers ONLY from this sheet. Each entry names its source artifact. If a number is not here, do not invent it: look in the named source, add it here first.*

Conventions: P_fail = logical failure probability per shot; ε = logical error per round = ½[1 − (1 − 2 P_fail)^(1/T)]; f = (ε_A − ε_X)/(ε_A − ε_B) = fraction of the perfect-flag (oracle) gain recovered; McNemar counts are "shots only the first decoder gets right / shots only the second gets right", exact two-sided binomial p.

## F1. The method (what is fixed in all experiments)
- Code: rotated surface code memory (Stim `surface_code:rotated_memory_z`), background noise SI1000 with strength p. Leakage model (phenomenological): each data qubit leaks with probability p_L per round, stays leaked for a geometric time of mean τ rounds, randomises each adjacent stabiliser outcome with probability ρ = 1/2 while leaked, receives a random Pauli on return, and flips its final readout with probability ρ if leaked at the end. Source: c3_manuscript.tex §2; leakage_sim.py.
- Decoder rule (same for every tracker): per shot, every matching-graph edge e touched by a possibly-leaked qubit gets probability p_e ← p_e ⊕ c·π, with c = ρ for the time-like edges of adjacent checks, 2/3 for the X/Z data edges at the return round, ρ for the final data-readout edge; π < 0.02 ignored. Derivation: derivation_soft_weight.md. PyMatching 2.4 minimum-weight matching.
- Trackers: (i) old HMM (per-qubit 2-state hidden Markov model, detection events treated as independent across rounds, true parameters given); (ii) old CNN (3 causal 3×3×3 conv layers, 32 channels, trained on 5×10⁴ simulated shots with true leakage labels, 6 epochs, lag 2); (iii) **ALL** (xa_tracker.py v2): per-data-qubit HMM whose hidden state also contains the measurement-flip bit of each neighbouring check ("explaining away"), all neighbouring checks of both bases, exact undecomposed detector error model, 8 damped Jacobi mean-field passes (damping 0.5) between neighbouring data qubits, label-free Baum to Welch calibration of per-qubit p_L and global return probability (12 iterations from p_L = 3e-3, p_ret = 0.25), ρ fixed at 1/2. Source: detect2_protocol.md v2.
- Controls: A = plain MWPM; B = oracle (true flags; simulation only); A4 = static control (each shot gets the mean posterior over all shots); P = placebo (each shot gets another shot's posteriors, fixed permutation seed 0). Source: ibm_stab_protocol.md.

## F6. False-alarm boundary and v3 (synthetic only), source: miami_precheck.md, v3_dev_protocol.md v3, v3_dev_results.md, v3_confirmation.md
- On leak-free simulated data the frozen tracker ALL (v2) invents leakage: reset d = 5 memory, p = 2e-3, no leakage: EM fits p_L 1.1e-3 with p_ret 0.98 (one-round fake episodes), P_fail 0.0174 → 0.0208 (47 / 81). On ibm_miami-style no-reset circuits (Zenodo 21336494, authors' calibration noise, no leakage): d = 3 memory exact model 0.031 → 0.044 (77 / 225); with real noise 1.7× the model 0.089 → 0.168 (359 / 1299), 0.089 → 0.110 after label-free rescaling (174 / 417); d = 5 memory with 1.5× noise 0.365 → 0.418.
- ibm_miami label-free facts: real detection fractions are 1.5 to 1.7× the authors' calibration model and rise with depth (d = 3 placement 5: 0.084 → 0.107 from depth 2 to 32). "Defects ignored" stability runs are random (published MWPM failure 0.45 to 0.49).
- v3 = R (readout explaining away for no-reset circuits) + G2 (per-run switch-off test: keep a data qubit only if its held-out likelihood gain exceeds the largest per-qubit gain on leak-free data simulated from the model). Chosen by a rule fixed in advance (dev seed 7000: no harm in three null scenarios; summed gain +0.22 vs +0.10 for the runner-up). **Confirmation on new seeds (8000) FAILED rule 1**: reset leak-free d = 3 memory 88 / 121, p = 0.027 (+3.4 % failures). Other null scenarios: 58 / 47 (p = 0.33) and 0 / 0. Leakage scenarios: 655 / 359, 128 / 106, 154 / 109, 58 / 45. By the pre-set rule v3 was NOT run on ibm_miami.
- Diagnostic: ibm_berlin-type stability circuit (T = 50, uniform p = 6e-3, seed 7000): no leakage → MWPM 0 failures in 20 000 shots (nothing to harm); 2 long-lived hot qubits (p_L = 3e-3, τ = 40) → MWPM 0.0075, tracker 0.0034 (114 / 34, p = 3e-11), v3 0.0037 (109 / 35). Reading: stability experiments fail mostly through long-lived states, so the tracker is strong and safe there; memory experiments have smaller oracle gains (4 to 26 % here) that a few false alarms cancel.

## F8. Corrections and additions after the external review (26 Oct 2026). These override anything above that conflicts.
- Episode length on ibm_berlin: fitted p_ret 0.013 to 0.033 at α = 0 means mean episodes of 1/0.033 ≈ 30 to 1/0.013 ≈ 77 rounds (not 100). These are longer than the T = 5, 10 and 20 runs, so in those runs p_ret is barely constrained.
- Label-free evidence per round: 1.0 nats/shot at T = 5 is 0.20 nats per round; 8.2 at T = 100 is 0.08 per round. Per-shot nats grow with T by construction. The evidence has no null yet on ibm_berlin; the null check (leak-free shots sampled from each shipped DEM, same calibration) is being run; results go into F9 when done.
- Self-switch-off: for α ≥ 0.8 the fitted mean p_L is 0.7×10⁻⁴ to 5×10⁻⁴ (write it this way). Wording: when readout noise buries the signal, the fit returns near-zero leakage and the decoder falls back to MWPM. Do not write "nothing to find"; it is the same chip and presumably the same state. At T = 20 the gain is not monotone in α (−5.8 % at 0, −8.0 % at 0.3); say "vanishes for α ≥ 0.8", not "shrinks".
- Missing intervals: T = 50: −15.3 % [−17.5, −13.0]; T = 100: −20.4 % [−23.0, −17.7].
- X vs static control A4 per run: 11 wins (one of them, T = 20 α = 0.8, by 2 shots to 0), 3 losses (T = 5, T = 10, T = 20 α = 0.6), 3 exact ties (T = 20 α = 1.0, T = 100 α = 0.8, T = 100 α = 1.0). Note α ≥ 0.8 covers 4 runs, not 3.
- Missing p-values: ALL vs J 7230 / 3769, p = 9.4×10⁻²⁴³; placebo P vs A 3 346 / 4 959, p = 1.9×10⁻⁷⁰; A_dec vs A 16 363 / 15 877, p = 0.0069 (modest).
- ρ wording (matches leakage_sim.py: `coins < rho; flips = leaked & coins`): while leaked, the qubit FLIPS each adjacent check outcome with probability ρ = 1/2, independently per check and round. The return Pauli is uniform over {X, Y, Z} (`rng.integers(0, 3)`), which is what c = 2/3 assumes. Do not write "randomises with probability ρ".
- Same two hot qubits: this alone cannot separate a physical cause from a systematic error of the given noise model on those qubits, because such an error would also repeat across runs on the same chip (F6 shows the tracker fits fake leakage when the DEM is off, by amounts that differ per qubit). The per-shot evidence is X > A4 and P < A.
- What is learned and what is given: the tracker learns p_L per qubit and one p_ret from the device's syndromes. ρ is fixed at 1/2. The background error model is given: the exact circuit DEM in simulation, the authors' shipped p_ij DEM on hardware. A mismatch of that given model is what makes the false alarms in F6.
- Abstract numbers: quote the held-out setting p = 3×10⁻³ (AP 0.818 vs 0.647; f 0.41 vs 0.22; McNemar 930 / 760, p = 4×10⁻⁵), not p = 2×10⁻³ hom, which is the development configuration (new seed, same settings) and where decoding ties. The pooled McNemar 2840 / 2551 is over p = 2 and 3×10⁻³.

- RULE FOR TEXT: never quote the raw evidence as proof of leakage. Always add the caveat that the null model does not match the data's detection fraction, so this is not a clean leakage test.

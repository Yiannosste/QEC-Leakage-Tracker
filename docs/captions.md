# Figure captions, "Syndrome-only leakage tracking for matching decoders: when does it help?"

**Symbols used in every figure.** A *leaked* data qubit has left the computational subspace; in the simulator it randomises the outcomes of its four neighbouring stabiliser checks with probability ρ = 1/2 each round and returns after a lifetime of about τ rounds, carrying a random Pauli error. p_L is the leakage probability per data qubit per round. The *detection fraction* is the share of stabiliser checks that fire (change value) in a round. P_fail is the probability that the logical observable is wrong after R rounds (R = 25 everywhere except the Willow run, R = 30); the *logical error per round* is ε = ½[1 − (1 − 2 P_fail)^(1/R)]. Decoders: *no flags* (A) is plain minimum-weight perfect matching (MWPM, PyMatching) on the Pauli-only error model; *oracle flags* (B) gives the decoder the true leak state; *soft weights* (D) replace each edge probability by p_e = p_e⁰ ⊕ c·π, where π is the tracker's posterior leak probability and c is a fixed constant per edge class; *hard flags* (E) apply the same change only where π > 0.5. The trackers see nothing but the syndromes: an HMM (lag 0) and a 3-layer causal CNN that may wait 0 or 2 rounds ("lag") before emitting π. The *fraction of the oracle gain* is f = (ε_A − ε_X)/(ε_A − ε_B); f = 1 means the tracker is as good as perfect flags and f = 0 means no improvement. Unless stated otherwise, intervals are 95 % Fieller intervals on f and all decoders in one panel were run on identical shots.

## Figure 1, The model, the decoder chain, and where syndrome-only soft weights stand against every leak-blind baseline

**(a)** Phenomenological leakage model and decoding chain. Left: a leaked data qubit (red circle) randomises its four adjacent stabilisers (red squares) with probability ρ for about τ rounds and returns with a random Pauli error. Right: the syndromes feed a tracker (HMM or CNN) that outputs a posterior π for every qubit and round; π raises the MWPM edge probabilities shot by shot (soft weights) or, in the hard-flag variant, only where π > 0.5. Definitions of ε, f and detection fraction as above.
**(b)** Detection fraction per round in the simulator at d = 5, p = 10⁻³ (validate_rise.csv, 25 rounds): with no leakage the curve is flat at ≈ 0.024; with leakage it rises during the run because leaked qubits accumulate until lifetime and injection balance (p_L = 10⁻³ and τ = 3 or 10; p_L = 3×10⁻³, τ = 10). The dashed curve adds a leakage-removal unit (LRU) of efficiency η = 0.9 per round, which removes most of the rise.
**(c)** Primary grid: f for the HMM soft weights (orange) and the CNN soft weights with lag 2 (blue) in all 27 cells of the p = 10⁻³ SI1000-type background, d ∈ {3, 5, 7} × p_L ∈ {1, 2, 5}×10⁻³ × τ ∈ {4, 8, 16} rounds, n = 10⁵ shots per cell (statistics_f_table.csv). CNN soft weights recover 0.60 to 0.90 of the oracle gain and the HMM 0.37 to 0.75; the CNN beats the HMM in all 27 cells and all intervals exclude 0 (Holm-corrected McNemar tests). Hollow blue markers: the CNN was trained at the d = 7 centre cell (p_L = 2×10⁻³, τ = 8) and applied without retraining to the other d = 7 cells and to d = 9. The d = 9 points (n = 5×10⁴, scaling_results.csv) carry bootstrap intervals. Green squares: a static data-fitted error model (per-edge-class factors learned on 2×10⁴ leaky calibration shots, no per-shot information), available at five cells, shown without an interval (its bootstrap interval is on the P_fail-based f).
**(d)** Baseline ladder at the d = 5 centre cell (p_L = 2×10⁻³, τ = 8), same 10⁵ shots for every row (baselines_results.csv): belief matching with no leakage information (f = 0.17), a detection-count heuristic (window 3, lag 2; 0.34), the static learned error model (0.42), HMM soft weights (0.51), CNN hard flags (0.65), CNN soft weights (0.72) and belief matching with the CNN posterior folded into its hyperedge priors (0.77). Bars are paired-bootstrap 95 % intervals. In this panel f is computed on P_fail rather than ε so that the identical-shot bootstrap intervals of the baselines run apply; the ε-based values differ by at most 0.01 (e.g. 0.727 vs 0.720 for CNN soft weights).

## Figure 2, Scope: syndrome-only leakage tracking helps only where leakage dominates a clean background, and today's public hardware is not there

**(a)** Reduction of the logical error per round relative to plain MWPM, 100·(1 − ε_X/ε_A), for oracle flags (hollow black) and CNN soft weights with lag 2 (blue), against the background detection fraction. Circles: simulator at d = 5, p_L = 10⁻³, τ = 8 with background Pauli noise p = 1, 2, 3×10⁻³ (n = 10⁵ shots each; final_cells.csv and the G5 result files): the oracle gain falls from 76 % to 29 % and the tracker's from 56 % to 8 %. The hollow blue circle is the same p = 3×10⁻³ cell with a CNN trained on 2×10⁵ instead of 5×10⁴ shots (12 %). Squares: Google Sycamore 2023 data (real_data_results.csv), eight d = 3 runs pooled (4×10⁵ shots) and two d = 5 runs pooled (10⁵ shots); the tracker point is measured on the hardware syndromes, the oracle point on a simulator with the device Pauli model plus leakage fitted to each run's detection-fraction curve, because no leakage ground truth exists for hardware. Diamond: Google Willow 2025 d = 3 memory-Z run (one patch, 5×10⁴ shots, R = 30; willow_results.csv); tracker on hardware (CNN trained on the T1 model, SI1000 prior; with the RL-optimised prior the ratio is 0.987 [0.968, 1.007]), oracle on the "upper-limit" model (τ = 4, p_L = 3×10⁻⁴, the 95 % upper bound allowed by the flat curve), so the oracle value is an upper limit. The detection fraction of the hardware points is the mean over bulk rounds. Error bars: 95 % Wilson interval on ε_X with ε_A fixed (simulator) or paired-bootstrap 95 % intervals on the ratio (hardware). Dotted links join oracle and tracker at the same point.
**(b)** Oracle-flag error reduction against code distance at 2023-like noise (p = 6×10⁻³, p_L = 2×10⁻³, τ = 8, n = 5×10⁴ shots per point; G6 result files): ε_A stays at 2.1 to 2.3 % for d = 3 to 9 (the code is at threshold) and even perfect flags remove only 9 to 27 % of ε.
**(c)** Leakage share of ε_A, 100·(1 − ε_ref/ε_A) with ε_ref the same decoder on the same background without leakage: 90 % at p = 10⁻³ and 45 % at p = 3×10⁻³ (d = 5, p_L = 10⁻³, τ = 8). For the hardware-fitted models no leakage-free run of the same device exists; the hollow markers show the oracle gain from (a), a lower bound on the share (3 to 10 %).
**(d)** f against background noise p for CNN soft weights, CNN hard flags and HMM soft weights in the same cell as (a); the hollow blue point is the 2×10⁵-shot CNN. (The p = 2×10⁻³ HMM point is the lag-2 HMM, the only HMM run in that file.)
**(e)** Learning curve at p = 3×10⁻³: f against the number of CNN training shots (learning_curve.csv; 6 to 10 epochs); quadrupling the data raises f from 0.28 to 0.43.

## Figure 3, Soft weights beat hard flags from the same posterior, and keep their value when hard flags fail

**(a)** f with soft weights against f with hard flags from the *same* posterior, for all 27 cells of Fig. 1c and both trackers (final_cells.csv, ε-based f). Soft weights win in 53 of 54 comparisons; the grey line is equality.
**(b)** Herald-equivalence map: f obtained when the decoder receives *corrupted oracle flags* of a chosen recall and precision (hard flags), at the d = 5 and d = 7 centre cells (p_L = 2×10⁻³, τ = 8; herald_*.csv). The printed value in each cell is f. The circles mark where the real trackers' hard flags sit (recall, precision from g1_results.csv: HMM 0.68/0.34, CNN lag 2 0.73/0.86 at d = 5); their hard-flag f agrees with the map, and their soft-weight f (text below the map) is higher than what any hard flag of that quality can give.
**(c)** Sensitivity to the weight constant c: f for CNN soft weights when c is multiplied by s for one edge class at a time (time-like edges, return edges, final-round edges; d = 5 centre cell, n = 5×10⁴ shots, baselines_results.csv). f stays between 0.66 and 0.73 for s ∈ [0.5, 1.5]; bars are paired-bootstrap 95 % intervals.
**(d)** Leakage-removal units: f at the d = 5 centre cell against the per-round removal efficiency η (η = 0: g1_results.csv; η = 0.5 and 0.9: LRU result files with a CNN retrained on the matching simulator; the HMM at η = 0.9 from g3_results.csv). Hard flags (dashed, hollow) fall to zero (HMM) or 0.09 (CNN) while soft weights keep f = 0.21 (HMM) and 0.43 (CNN) at η = 0.9. f in this panel is P_fail-based with paired-bootstrap 95 % intervals.
**(e)** Leakage transport: f against the probability p_t that a leaked qubit hands its leakage to its CZ partner (realism_results.csv; d = 3 dotted/hollow, d = 5 solid; p_L = 2×10⁻³, τ = 8, no measure-qubit leakage, 1/3 return-Pauli model). The CNN is retrained for each transport setting; the crosses show the d = 5 CNN trained without transport. The HMM, whose model assumes a leaked qubit stays put, loses most of its value at p_t = 0.3 at d = 5 (f = 0.09), the retrained CNN keeps f = 0.50. Only soft-weight decoders were run in this track, so no hard-flag points are shown. f is P_fail-based with Fieller intervals.

## Figure 4, Latency: flags that arrive late are worth much less, and an online decoder must wait about one leakage lifetime to recover the gain

**(a)** f for oracle flags delivered D rounds late (the decoder learns of a leak D rounds after it starts), at d = 5 (black) and d = 7 (grey), p_L = 2×10⁻³, τ = 8, n = 10⁵ shots (latency_grid_new.csv, after the exponent fix). f = 0.62 (d = 5) and 0.78 (d = 7) at a 2-round delay and 0.25 / 0.44 at 5 rounds. Blue: the lag-2 CNN posterior, either used after the decoder waits 2 rounds (D = 0, f = 0.75) or applied immediately so that it arrives 2 rounds late (D = 2, f = 0.57).
**(b)** A genuine sliding-window decoder at the d = 5 centre cell (streaming_results.csv, n = 10⁵ shots). Each window commits W_c rounds and sees W_l further rounds of look-ahead; the CNN posterior uses only the rounds inside the window. Points: ε (log scale) for no flags (grey), CNN soft weights (blue) and oracle flags (hollow black); dashed lines: the same decoders decoding the whole 25-round run at once (batch). With a 2-round look-ahead the windowed decoder is worse than batch MWPM even with perfect flags (no flags: 2.70, 2.34, 2.07×10⁻³ for W_c = 3, 5, 10 vs 1.61×10⁻³ batch), and this holds with no leakage at all (ε rises from 0.80 to 1.93×10⁻⁴ at W_c = 3, p_L = 0). A look-ahead of 5 or 8 rounds (≈ τ) brings the no-flag decoder back to 1.84 and 1.67×10⁻³ and the CNN recovers f = 0.56 and 0.61 of the within-window oracle gain.

## Figure 5, On public hardware data the trackers find leakage-like events but do not improve the decoder, as the scope argument predicts

**(a)** Detection fraction per round. Left: Sycamore 2023 d = 5 memory-X run (hardware, black; fit_leakage.json), the device Pauli model with no leakage (grey) and the Pauli model plus leakage fitted to the curve (red dashed; p_L = 2.0×10⁻³, τ = 8, 1.2 % of data-qubit-rounds leaked): the hardware sits ≈ 0.015 above the Pauli model over the bulk rounds. Right: Willow 2025 d = 3 memory-Z run with per-round data-qubit leakage removal (fit_leakage_willow.json): the curve is flat (mean 0.075, slope −2.4×10⁻⁵ per round over rounds 1 to 28) and is matched by a scaled SI1000 model with no leakage (scale s = 3.01); long-lived leakage is bounded to ≤ 0.1 % of qubit-rounds.
**(b)** Flag plausibility on Sycamore 2023 (values parsed from Table 3 of real_data_report.md). For every qubit-round the lag-0 CNN flags (π > 0.5), the detection fraction of that qubit's four neighbouring checks in the *next* round (not seen by the tracker) is 0.36 to 0.42 (filled red) and 0.30 to 0.38 two rounds later (hollow), against 0.15 to 0.17 after unflagged qubit-rounds (grey), in all ten runs (bases X/Z, d = 3 patches centred at the listed coordinates, d = 5). The model's prediction for a truly leaked qubit is 0.5; the flags therefore mark real, persistent, localised anomalies. n = 13k to 228k flags per run.
**(c)** ε ratio to plain MWPM on the hardware syndromes (real_data_results.csv, willow_results.csv): Sycamore d = 3 (8 runs pooled, 4×10⁵ shots), d = 5 (2 runs pooled, 10⁵ shots), Willow d = 3 (1 run, 5×10⁴ shots, R = 30, SI1000 prior). Decoders: a static model-averaged error model (A4), HMM soft weights, CNN soft weights with lag 0 and lag 2, CNN hard flags with lag 0. Every ratio lies between 0.980 and 1.014; no decoder is better than plain MWPM after Holm correction (the Willow CNN lag-2 value 0.980 has p = 0.049 uncorrected and is not reproduced with the RL-optimised prior). Bars: paired shot-level bootstrap 95 % intervals.
**(d)** The same decoders on the fitted simulators where the oracle exists (set = sim; 1.6×10⁵, 4×10⁴ and 2×10⁴ shots): perfect flags would remove 3 % (d = 3) and 10 % (d = 5) of ε on the 2023 models and 4 % on the Willow upper-limit model (τ = 4, p_L = 3×10⁻⁴; only HMM and the static model were run there). The trackers recover almost none of this small gain. The 2023 oracle values are simulator quantities, not hardware measurements.

## Declared caveats (apply across figures)
- d = 7 non-centre cells and both d = 9 cells use the CNN trained at the d = 7 centre cell without retraining (hollow markers in Fig. 1c); the HMM has no training step.
- Willow 2025 values use R = 30 rounds in the ε conversion (all others R = 25) and a single patch/basis.
- The 2023 and Willow "oracle" values come from fitted simulators, because hardware has no leakage ground truth; the Willow oracle is an upper limit.
- f is ε-based with Fieller intervals in Figs 1c, 2d, 3a and 4a; it is P_fail-based with paired-bootstrap or Fieller intervals in Figs 1d, 3c, 3d, 3e and the within-window f of Fig. 4b (differences ≤ 0.01 at the cells checked).
- Fig. 2a/c simulated error bars are Wilson intervals on ε_X with ε_A held fixed, not paired intervals.
